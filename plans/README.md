## Vetted findings covered

1. The release window points to `127.0.0.1:4317`, but the bundle embeds neither frontend assets nor a server sidecar.
2. CSP is disabled, the global Tauri object is injected, and release builds enable devtools.
3. Timer, task, and settings rules live inside Leptos components and cannot be tested independently.
4. Home state is destroyed by navigation, and each remount creates an interval that is never cleared.
5. Timer accuracy assumes every browser callback represents exactly one elapsed second.
6. There are no tests and no pull-request CI; root checks also omit the separate Tauri workspace.
7. The custom-port recipe does not match the configured `127.0.0.1` URLs and repository setup hides tracked mobile configuration changes.
8. Tool versions float, release CLIs are rebuilt without caching, and the pnpm lockfile contains a high-severity build-path advisory.
9. `ARCHITECTURE.md`, `CONTRIBUTING.md`, security/community files, and PR/issue templates are absent.
10. README and AGENTS contradict the current local-server runtime and overstate installer readiness.

## Direction after these plans

- Make durable local focus history the first new adapter-driven feature. It replaces the dashboard's static totals/chart and proves the repository port with real data.
- Emit a `SessionCompleted` domain event and add an optional Tauri notification adapter. This is a bounded example of extending the application without importing Tauri into the core.
- Replace the single priority string and hard-coded completion count with a typed daily priority list after persistence has a versioned schema.

## Findings considered and rejected

- Generic plugin system: rejected for now. Stable ports for storage, clock, and notification provide extension points without committing to an unproven plugin ABI.
- Rust server sidecar as the default desktop runtime: rejected as the recommendation because this is a local-first app and the current server has no product backend behavior. Keep Axum only as an optional web/SSR adapter unless an ADR establishes a real sidecar requirement.
- One Cargo crate per hexagonal layer: rejected as premature. Start with one pure `focus-flow-core` crate containing domain and application modules; split it only when compile times, ownership, or independent reuse justify it.
- Mobile expansion: deferred until macOS and Windows packaged builds are independently usable and tested.
