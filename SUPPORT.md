# Support policy (draft)

This document is a draft. Maintainers must approve and configure the channels
below before publication; no contact addresses or external channels are
invented here.

## Where to ask

- Usage and setup questions: a maintainer-approved support channel (not yet
  configured).
- Reproducible, non-sensitive bugs: use the bug report form after the
  repository owner confirms the canonical repository URL and enables it.
- Feature ideas: use the feature request form after the canonical repository
  URL is confirmed.
- Security concerns: follow [SECURITY.md](SECURITY.md); never post sensitive
  details publicly.

The issue forms are publication placeholders, not live contact channels. Do
not use public issues for private, urgent, or security-sensitive matters.

## Include useful context

For a bug, include the app version or commit, operating system, reproduction
steps, expected behavior, actual behavior, and relevant non-sensitive logs.
For a feature, describe the user value, proposed behavior, alternatives, and
trade-offs. Search existing issues first and keep one topic per report.

## Maintainer checklist before publication

- Choose real channels for questions, bug triage, feature discussion, and
  private security reports.
- Add approved links and owners to this file and the repository settings.
- Confirm response expectations and who maintains the issue forms.
